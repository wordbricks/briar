# DM 메시지와 명시적 선호

이번 구현 범위는 실행 중 공개 메시지와 기존 명시적 선호의 저장·수정·삭제다.
관찰로 선호를 추론하거나 후속 확인, 알림 정책, 장기 작업 제어를 추가하지 않는다.

## 완료 기준

- Agent가 작업을 마치기 전에 DM에 공개 메시지를 보낼 수 있다.
- 한 번에 보낸 여러 메시지는 서버 순서대로 보이며, 인접한 같은 묶음은 이름과 아바타를 공유한다. 웹·Android·iOS에 적용한다.
- 같은 전송 요청을 재시도해도 메시지가 늘어나지 않는다. 마지막 메시지를 이미 보냈다면 작업 완료가 이를 다시 만들지 않는다.
- 사용자가 명시한 선호는 기존 DM memory 처리로 저장되고 다음 실행의 brief에 들어간다. 수정하면 최신 내용만 남고, 삭제하면 내용과 인용이 사라진다. 다른 문서는 유지한다.

## 구현 경계

공개 메시지는 기존 Worker claim 권한 안에서 `PublishDmMessageBatch`로 전송한다.
서버가 묶음 ID와 메시지 순서를 부여하고, 기존 완료 요청이 마지막 묶음을 참조한다.
일반 대화와 기존 클라이언트의 메시지는 기존 시간 순서를 유지한다.

명시적 선호에는 새 테이블이나 RPC를 만들지 않는다.
현재 요청은 사용자의 지시를 직접 따르고, 저장된 선호는 기존 비동기 memory 처리가 끝난 뒤 새 claim에 반영된다.
이를 즉시 동기 저장이나 강제 행동 정책으로 표현하지 않는다.

## 검증

기존 DM memory 실행 및 CLI 테스트에 한 선호의 저장 → 새 brief → 수정 → 새 brief → 삭제 흐름을 추가했다.
언어 선호와 무관한 프로젝트 코드명 문서가 남는지도 함께 확인한다.

메시지 검증은 서버 전송·재시도·완료 중복 방지와 각 클라이언트의 순서·묶음 표시를 확인한다.
iOS는 메시지 변환·저장소·표시 테스트와 시뮬레이터 화면 검증을 사용한다.
테스트 fixture의 문구는 실제 작업 결과를 뜻하지 않는다.
