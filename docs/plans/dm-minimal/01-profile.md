# SPEC 1. profile.md로 기억하고 답변에 참고하기

## 목표

“나는 PM이고 설명은 결론부터 짧게 해줘”를 기억하고, 이후 관련 질문에 적용한다.
사용자가 수정하거나 잊으라고 하면 다음 답변부터 바뀐다. 별도의 행동 정책 엔진은 만들지 않는다.

## 현재 있는 것

- `src-cli/dm-memory-invocation.ts`는 claim의 brief로 비공개 `profile.md`를 만들고 답변 prompt에 전달한다.
- `worker/src/dm-memory-brief.ts`는 기존 profile 문서를 최대 4,096 bytes의 본문 예산으로 묶는다.
- 기존 memory 문서·revision, 학습 proposer/verifier, 소유자 opt-in, 수정·삭제·실행 fence가 있다.
- 명시 선호의 저장 → 다음 claim → 수정 → 삭제 흐름은 이미 검증했다.

따라서 저장 시스템을 새로 만들지 않는다. 이 SPEC의 차이는 특징·선호를 읽기 좋은 내용으로 유지하고,
관련 답변에서 실제로 참고하도록 기존 경로를 보완하는 것이다.

## 최소 동작

1. 기억 기능을 켠 DM에서 기존 학습 경로가 사용자가 밝힌 안정적인 특징과 선호를 profile 문서로 저장한다.
   예: 역할, 익숙한 기술, 선호 언어, 설명 깊이, 결과 형식. 일회성 요청은 지속 선호로 승격하지 않는다.
2. 기존 `profile.md`를 짧은 Markdown 항목으로 렌더링한다. 사용자 특징과 답변 선호를 구분하고,
   적용 범위가 있으면 같은 항목에 적는다. source ID/version은 기존 내부 메타데이터를 유지한다.
3. 답변 Agent는 현재 요청과 관련된 항목만 참고한다. 현재 사용자의 지시가 저장된 선호보다 우선한다.
   기억을 매번 설명하거나 답변에 profile 전문을 붙이지 않는다.
4. “이제 자세하게 설명해줘”, “그 선호는 잊어줘”는 기존 정정·삭제 경로로 처리한다.
   진행 중 실행의 오래된 기억은 기존 fence로 차단한다.
5. 현재 발언은 현재 답변에서 바로 따른다. 영구 저장은 기존 비동기 학습으로 처리하며,
   서버 저장 확인 전에는 “저장했다”고 말하지 않는다.

## 저장·적용 원칙

- D1의 기존 memory 문서가 원본이고 `profile.md`는 실행마다 만드는 읽기용 파일이다.
  Agent가 로컬 파일을 편집해도 저장으로 간주하지 않는다. 사용자에게 파일 동기화를 맡기지 않는다.
- 소유자와 Agent로 구분된 기존 memory space를 유지한다. 다른 Agent/DM으로 자동 공유하지 않는다.
- 기존 4KB 본문 예산과 완전한 항목 선택을 유지한다. 예산을 넘으면 기존 검색 경로를 사용한다.
  매 답변마다 별도 요약 모델을 호출하거나 profile 전체를 다시 쓰지 않는다.
- 사용자가 직접 밝히거나 정정한 내용을 우선한다. 행동만 보고 성격·민감한 특징을 추측하는 기능은 제외한다.
- 저장할 변경이 없는 대화는 profile revision을 만들지 않는다. 기존 verifier와 권한 검사를 우회하지 않는다.

## 변경 위치

`apps/briar/src-cli/dm-memory-invocation.ts`의 파일 표현·답변 지침,
기존 `dm-memory-learning*`의 profile 분류·정정 지침을 필요한 만큼 보완한다.
`apps/briar/worker/src/dm-memory-brief.ts`는 기존 선택·예산이 목표를 충족하면 변경하지 않는다.
새 테이블·새 RPC·별도 profile 편집 화면은 만들지 않는다. 기존 기억 관리 화면에서 조회·수정·삭제한다.

## 완료 기준

- 실제 학습·저장 후 새 실행에서 언어·설명 깊이·역할 관련 답변이 달라진다. 최소 3개 서로 다른 선호로 확인한다.
- 현재 요청의 반대 지시가 우선하며, 무관한 질문에는 기억을 억지로 적용하지 않는다.
- 수정 후 이전 선호가 적용되지 않고, 삭제 후 파일·brief·인용에서 사라진다. 무관한 기억은 남는다.
- 다른 사용자/Agent의 profile을 읽지 못하며 opt-out이면 전달되지 않는다.
- 실제 지원 provider로 저장 전/후 답변을 한 번 비교한다. 프롬프트 snapshot 검사만으로 대체하지 않는다.

## 제외

선호별 전용 테이블, 신뢰도 점수 체계, 행동 추론 엔진, 같은 turn의 동기 학습,
조건·시간대별 정책 집행, 전체 과거 대화 재학습, 새로운 벡터 검색 시스템.
