# DM 첫 리액션 검증 (#7011)

## 변경 동작

- DM 작업 생성 시 고정 👀를 저장하지 않는다. Worker는 최근 메시지 최대 10개와 반응 대상 사용자 메시지(최근 10개 밖에 있으면 추가하여 최대 11개), 각 본문 최대 4,000자를 읽는 별도 모델 호출을 시작하고 본문 작업을 계속한다. 원래 대화 순서를 유지하며 대상 메시지가 최근 10개 안에 있으면 중복하지 않는다.
- 선택 호출은 동일한 provider/model, 낮은 추론 강도, 새 대화, 읽기 전용 임시 작업 공간을 사용한다. Skill·Computer Use·DM 게시 도구를 부여하지 않고, 대화 텍스트를 지시로 따르지 않도록 명시한다. 키워드 매핑은 없다.
- 15초 시간 초과, 모델 실패, 잘못된 결과는 👀로 정리한다. 게시 요청도 3초로 제한하며 실패가 본문에 전파되지 않는다. 본문이 더 빨리 끝나면 완료 트랜잭션에서 누락된 리액션만 👀로 채운다. 선택 지연 때문에 답변을 늦추지 않으므로 이 예외에서는 리액션과 완료가 함께 보일 수 있다.
- 현재 클레임의 서명된 capability를 사용한다. 서버가 Worker·기기·클레임 토큰·만료·DM 문맥 권한을 확인하고 INSERT 안에서도 조직, DM 종류, 사용자 작성 메시지, Agent 참여 및 현재 실행 권한을 다시 확인한다.
- 메시지와 해당 Agent에 리액션이 있으면 추가/삭제/교체하지 않는다. 첫 INSERT가 이기며 사용자 및 다른 Agent의 리액션은 보존한다. 답변 완료 결과에 실린 예전 이모지 필드는 교체에 사용하지 않는다.
- 기존 메시지 동기화 트리거 및 실시간 알림으로 화면을 갱신한다. 테이블 변경이나 데이터 마이그레이션은 없다.

## 실제 모델 측정

2026-09-09 KST, 이 작업 트리에서 빌드한 Codex runner와 현재 로컬 Codex 기본 모델을 사용했다. 모델 ID는 이 측정에서 별도로 고정하거나 기록하지 않았다. 실제 DM 본문 프롬프트(`detachedChannelReplyPrompt`)와 이모지 선택을 동시에 실행했다. 외부 사용자에게 메시지를 보내거나 운영 DM을 만들지 않았다. 게시 콜백의 시각을 기록했으며, 서버 저장/동기화는 별도 D1 테스트로 검증했다.

| 문맥 | 최초 리액션 | 선택/게시 콜백 | 본문 모델 완료 |
| --- | --- | ---: | ---: |
| 끝말잇기 게임 요청 | 🎮 | 4,834ms | 8,446ms |
| 첫 고객 계약 성공 | 🎉 | 5,098ms | 8,440ms |
| 전날 도움에 대한 감사 | 💛 | 4,830ms | 7,907ms |
| 면접 결과를 묻는 대화 후 “떨어졌어. 너무 속상하다.” | 🫂 | 4,475ms | 7,791ms |

네 기록 모두 최초 리액션 이벤트 1개가 본문 완료보다 앞섰으며, 그 전에 👀 이벤트는 없었다. 모델만 단독 실행한 추가 네 사례에서도 5,017–6,715ms에 🎮/🎉/💛/🫂가 선택됐다. 이 수치는 운영 지연시간 보장이 아니다.

## 자동 및 화면 검증

- 리뷰에서 발견된 오래된 대상 메시지 누락을 수정했다. 20개 메시지 스냅샷에서 대상 위치 0·9·10·19 각각을 검사하여 대상 본문과 표시가 정확히 한 번 포함되고 대화 순서와 최대 11개 제한이 유지되는 회귀 테스트를 추가했다.
- 선택 실패/시간 초과/늦은 성공 무시/중단/게시 실패 격리, 비-DM 및 Agent 작성 입력 제외: CLI 단위 테스트.
- 최초 저장, 병렬 중복, 재시도 토큰 교체, 사용자·다른 Agent 보존, 최종 결과의 교체 금지, 본문이 더 빠른 경우 fallback, 잘못된 토큰/기기/Worker/만료, Agent 탈퇴, 삭제/Agent 작성 메시지, 일반 채널 제외 및 동기화 delta: D1 통합 테스트.
- 서명된 capability의 작업 불일치, 만료된 클레임, issue capability의 DM 리액션 거부, 실시간 알림 및 activity sequence 독립성: RPC 테스트.
- 실제 `ChannelMessageReactions`를 쓰는 로컬 fixture를 1100px 및 390px에서 실행하고 캡처했다. 이미지가 Briar 이슈의 UI rendering 증거에 첨부됐다. 본문 작성 중 표시는 fixture이며 실서비스 시간 순서의 증거로 사용하지 않는다.
- iOS의 `ChannelReactionBar`는 서버의 emoji 문자열을 표시하며 Android는 공유 companion 웹 컴포넌트를 사용한다. 모바일 소스 변경은 없다. 이 컴퓨터에는 `simctl`과 `adb`가 없어 네이티브 iOS/Android 표시는 실행 검증하지 못했다.

## 배포 경계 및 남은 검증

이 실행에 설정된 워크플로는 분석 → 구현 → 리뷰 → 로컬 CI → PR → signoff → main 병합으로 끝나며 배포 단계가 없다. 따라서 운영 서버 및 Agent 실행기 배포를 이 실행의 완료 사실로 주장하지 않는다. 릴리스 시 서버를 먼저 적용하고 새 실행기를 적용해야 한다. 서버만 갱신되고 이전 실행기가 남아 있는 동안은 본문 완료 시 fallback만 생길 수 있다.

운영 DM 최초 표시부터의 기록과 네이티브 iOS·Android 화면, 배포 버전 확인은 허용된 후속 릴리스/검증에서 수행해야 한다. 전체 로컬 CI와 병합 결과는 Briar 실행의 해당 단계 증거를 기준으로 한다.
